# SOCAVACION_LL — Constitution

> Borrador completado para revisión el 2026-10-09; no ratificado todavía.
> Recoge requisitos expresos del usuario y propone controles de calidad para
> completar el producto. La aprobación del borrador no valida nuevas ecuaciones.

## Known facts (from onboarding)

- Goal: Quiero desarrollar un software profesional de ingeniería civil para el cálculo de socavación general en ríos, torrenteras y puentes, utilizando exclusivamente el método de Lischtvan–Levediev para suel
- Project kind: software · software scope: growing
- How code changes land: straight on the default branch (`--workflow main`).
- Stack evidence: No stack evidence was detected at install. To be decided in the `constitution` phase.

## 1. Stack canon

1. Mantener Python de escritorio para Windows y el monolito modular existente.
   Runtime de desarrollo observado: Python3.12; interfaz PySide6. Dependencias en pyproject.toml.
2. Separar ingreso, cálculo, resultados y reportes. El núcleo no importa Qt,
   almacenamiento ni generadores de documentos; comprobar dependencias en pruebas.

## 2. Quality bar

3. Cada ecuación/coeficiente deberá indicar fuente, página, unidades y dominio;
   prevalecen los MTC designados por el usuario. Bloquear lo no sustentado.
   Referencias: proposals/proceso-calculo-normativa-local.md y proposals/base-calculo-v01.md.
4. Probar cada cambio de cálculo contra un desarrollo manual independiente y sus
   límites. Ejecutar la suite completa; no sustituir validación hidráulica por tests.
5. Propuesta para entrega completa: análisis estático y de tipos sin errores,
   cobertura de ramas del núcleo >=90%, revisión de dependencias sin hallazgos
   altos/críticos sin resolver. Umbral propuesto, no norma MTC; aún no implementado.

## 3. Conventions

6. Máximo250 líneas por módulo de producción; funciones, métodos y variables propios
   en español, salvo nombres exigidos por bibliotecas. Comprobación automática.
7. DRY: una evaluación alimenta pantalla y reportes. SOLID: separar responsabilidades
   e interfaces; KISS: no agregar servicios ni abstracciones sin necesidad verificable.

## 4. Branching & shipping

8. Mantener la elección de trabajo directo existente; no crear repositorios,
   ramas, publicaciones o commits por iniciativa propia. Actualmente no hay Git.
9. Si se utiliza Git, la autoría es humana; no atribuir commits a una IA.

## 5. Security & privacy floor

10. Validar archivos y números; no ejecutar contenido del proyecto. Guardado atómico,
    preservación ante fallo y migración que no sobrescribe originales silenciosamente.
11. Operación local sin envío de proyectos a servicios externos. No modificar los
    manuales originales ni el código de Metrados utilizado como referencia visual.

## 6. UX / accessibility floor (if there is a UI)

12. Interfaz y errores en español. Controles deshabilitados explican su causa;
    navegación por teclado, unidades visibles y confirmación al abandonar cambios.
13. Editar entradas invalida cálculos y reportes anteriores. Mostrar Hs, Sg algebraica
    y cotas por separado; no interpretar automáticamente Sg negativa como depósito.

## 7. Performance budgets (where they matter)

No se fija una cifra sin equipo/dataset de referencia. El plan de cada ampliación
deberá definir su tamaño máximo y una prueba medible antes de prometer rendimiento.

## 8. Knowledge & decisions

14. Registrar decisiones significativas con fecha, alternativas y motivo en decisions.md.
15. Aprobar cambios científicos antes de programarlos: ninguna autorización general
    equivale a aprobar interpolaciones, unidades ambiguas o un reparto de caudal inventado.

## Definition of Done (the merge bar `verify` runs against)

- [ ] Alcance, ecuaciones nuevas y plan aprobados.
- [ ] Criterios funcionales con pruebas observables; límites científicos explícitos.
- [ ] Pruebas, análisis estático, tipos, cobertura y dependencias con evidencia vigente.
- [ ] Módulos <=250 líneas, responsabilidades separadas e identificadores en español.
- [ ] Guardado/migraciones conservan datos; resultados nunca quedan obsoletos visibles.
- [ ] Reportes revisados visualmente y arranque local probado desde el proyecto Windows.
- [ ] Documentación y decisiones actualizadas; no afirmar certificación profesional.
